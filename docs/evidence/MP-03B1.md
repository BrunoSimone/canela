# Evidencia MP-03B1: contrato HTTP de checkout

## Fecha y entorno

- 2026-09-15.
- Next.js 16.2.9, TypeScript estricto y Vitest 5.
- PostgreSQL 17 efímero para integración.
- Checkout deshabilitado por defecto; no se crearon orders reales en este
  incremento.

## Requisito → implementación → prueba → resultado

| Requisito | Implementación | Prueba | Resultado |
| --- | --- | --- | --- |
| Feature flag seguro | `CHECKOUT_MODE` omite/deshabilita el endpoint y no construye dependencias externas | Smoke test HTTP sobre el build devuelve `404 CHECKOUT_DISABLED` | Aprobada |
| Ambiente controlado | El modo `test` exige configuración completa y una credencial separada por nombre de entorno | Configuración incompleta o uso de la variable genérica son rechazados | Corregida en MP-03B2: Mercado Pago documenta `APP_USR` también para prueba |
| Precio autoritativo | El body solo conserva IDs/cantidades; nombre y precio se releen de Sanity sin CDN | Campos `price`, `name` y `total` manipulados no llegan al caso de uso | Aprobada |
| Envío íntegro | Token HMAC versionado contiene importe, origen controlado y vencimiento | Token alterado o vencido falla antes de consultar catálogo o reservar | Aprobada |
| Idempotencia HTTP | Header `Idempotency-Key` validado y token público determinista por intento | Misma clave deriva el mismo token opaco; claves distintas se separan | Aprobada |
| Estado público mínimo | Lookup por SHA-256 del token y mapeo a cuatro estados presentables | Token inválido/desconocido devuelve el mismo 404; no se exponen IDs ni PII | Aprobada |
| Retorno no confiable | El endpoint de estado ignora query params y consulta exclusivamente Neon | Tests del handler verifican la respuesta desde el estado persistido | Aprobada |

## Contratos disponibles

- `POST /api/checkout`: validación, quote firmada, catálogo autoritativo,
  reserva y creación de Orders API cuando el modo de prueba esté completo.
- `GET /api/orders/{publicToken}/status`: `verifying`, `paid`,
  `not_completed` o `review_required`, siempre con `Cache-Control: no-store`.

## Límites

- Falta la pantalla de confirmación, redirección y polling con RTK Query;
  corresponde a MP-03B2.
- El inventario de desarrollo todavía no fue cargado con cantidades reales.
- El rate limit distribuido se configurará antes de exponer checkout fuera de un
  preview protegido; un contador en memoria no protegería funciones serverless.
- El modo productivo continúa rechazado por configuración hasta sustituir la
  tarifa controlada por Correo Argentino.
